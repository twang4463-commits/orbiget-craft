# ai-context — 对话历史的确定性压缩（可复用组件）

来自 **OrbiGet Craft** 的 AI 运行时：在不调用第二次模型的前提下，把任意长的
对话历史压进给定的 token 预算。纯函数、零依赖、零网络请求，可直接拷进任何
LLM 对话项目使用。

## 解决什么问题

LLM 应用的历史消息是唯一没有硬顶的注入块：聊得越久，单次请求越贵、越容易
撞上下文窗口。常见的两种做法各有代价——粗暴丢弃（老对话凭空消失）或 LLM
二次摘要（每压一次多一次调用、多一笔钱、多一处不可复现）。

本组件是第三条路：**全确定性管道**，只截断、只折叠，不丢内容、不调模型：

1. **近期保真**：最后 N 条消息原样保留（只做超长保护截断）；
2. **旧消息瘦身**：普通消息与旧工具结果按不同档位截断（工具结果只留
   「查过什么、结论是什么」）；
3. **预算折叠**：仍超预算时，把最旧的一批折叠成单条「早前对话摘要」块，
   每条消息一行——**留痕，不是丢弃**；
4. **幂等**：摘要块有统一标记（`COMPACTION_DIGEST_HEADER`），再次压缩时
   已折叠的内容原样并入新摘要，不会出现「摘要套摘要」。

多模态友好：`content` 可以是纯文本，也可以是 OpenAI 视觉格式的分片数组——
管道只截文本分片，图片分片原样保留（图片是「这一轮」的语义）。

## 目录结构

| 文件 | 内容 |
|------|------|
| `token-estimate.ts` | 中英混合 token 估算（CJK 1.5/字、英文 1/词、数字 0.25/位、标点 0.3/字符） |
| `context-compaction.ts` | 压缩管道：分层截断 + 摘要折叠 + 幂等保护 |
| `demo.ts` | 最小运行示例 |

## 用法

```ts
import { compressHistoryMessages } from './context-compaction'

// history: { role, content }[] —— content 是 string 或内容分片数组
const { messages, compacted } = compressHistoryMessages(history, { maxTokens: 180000 })
```

`maxTokens` 是**这条连接**的历史预算：200k 窗口的 API 连接用默认 180k；
网页端点这类「页面输入框才是硬约束」的通道传小预算（如 8k），老消息就会
在这里折成摘要而不是在别处被粗暴丢弃。

token 口径是**折算估算**（量级正确，非精确结算）：中文一篇的 BPE 成本比同
字数英文高约 50%，按分词逻辑折算才两头都接近。刻意不引真 tokenizer——
各家词表不同（DeepSeek/豆包/千问各一套），引入几 MB 依赖后仍只能猜。

## 运行示例

```bash
npm i -g tsx && tsx demo.ts
```

demo 构造 40 条长消息、把预算压到 500 token，打印压缩前后的条数与摘要块形态。

## 审计要点

1. **无网络、无存储**：整个目录零 `fetch`、零 IO，输入输出都是纯内存数组。
2. **不改语义**：只截断文本、只折叠最旧消息；近期消息、图片分片、已有的
   摘要内容都不会被改写。
3. **不摘要**：没有 LLM 调用，压缩结果完全由输入决定（可测试、可复现）。

## 来源与调参

分层档位（近期 6 条 / 旧消息 6000 字 / 工具结果 3000 字 / 预算 180k / 条数
硬顶 300）来自 OrbiGet Craft 长对话场景的实测调整：200k 窗口下输入成本可
忽略，正常对话几乎永远全量保真，只在逼近预算时才触发折叠。
