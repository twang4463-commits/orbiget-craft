# OrbiGet-Craft 数据分类与隐私说明表

## 目的

这份表用于统一判断：哪些行为只进入内部轨迹，哪些行为应作为前台项目日志展示，哪些行为需要明确隐私提示或权限说明。

它的目标不是减少记录，而是**减少误展示、误收集和产品语义混乱**。

## 基本原则

1. **项目激活态下可记录更多上下文，但不等于都要前台展示。**
2. **轨迹用于连续性，日志用于意义点，证据用于可追溯性。**
3. **用户主动动作优先进入日志流，系统自动动作优先进入轨迹流。**
4. **只记录为产品功能所必需的数据。**
5. **涉及浏览行为、页面内容、来源、时间戳等数据时，应默认按隐私敏感数据对待。**

## 数据分层

| 层级 | 定义 | 是否展示给用户 | 是否可回看 | 用途 |
| --- | --- | --- | --- | --- |
| 轨迹 | 浏览器内的连续行为记录 | 否，默认弱展示或折叠展示 | 是 | 保持创作过程连续性 |
| 日志 | 用户可感知的项目动作点 | 是 | 是 | 形成项目时间线 |
| 证据 | 可用于复盘、归因、取证的结构化记录 | 视场景展示 | 是 | 追溯来源与行为链 |

## 两类日志

OrbiGet-Craft 采用两类日志，而不是把所有记录混成一条时间线：

| 日志类型 | 记录对象 | 核心问题 | 默认显示位置 | 是否可编辑 |
| --- | --- | --- | --- | --- |
| 全局收集日志 | 素材与来源 | 这东西怎么来的 | 资产/收集箱上下文 | 否，内容源本身可改，但记录不可改 |
| 项目推进日志 | 项目过程 | 这个项目怎么往前走 | 侧边栏项目时间线 | 否 |

### 全局收集日志

用于记录素材采集事实，强调“来源”和“采集过程”：

- 来源 URL / 页面标题
- 采集方式
- 采集时间
- 所属项目或收集箱
- 采集时的上下文快照

它不负责表达“项目进度”，只负责表达“素材是怎么来的”。

### 项目推进日志

用于记录项目推进过程，强调“项目状态变化”和“创作行动”：

- 项目创建
- 素材入库到项目
- 来源确认
- 权利属性标记
- 里程碑
- 待办
- 编辑保存
- 导出
- 归档

它是用户回看、复盘、取证时真正面对的主日志流。

## 事件分类表

| 事件 | 默认分类 | 是否前台展示 | 隐私敏感度 | 备注 |
| --- | --- | --- | --- | --- |
| 打开网站 / 页面访问 | 轨迹 | 默认不展示 | 中 | 适合记录域名、时间、项目关联，不建议把每次刷新都当成日志点 |
| 页面停留 / 切换标签 | 轨迹 | 否 | 中 | 可作为上下文，不适合作为高亮日志 |
| 创建项目 | 日志 | 是 | 低 | 典型项目起点 |
| 激活项目 / 切换项目 | 日志 | 是 | 低 | 属于工作上下文变化 |
| 入库素材 | 日志 | 是 | 中 | 需记录来源、项目归属、时间 |
| 采集正文 / 截图 / 链接 | 日志 | 是 | 中 | 采集行为本身就是项目动作 |
| 用户主动输入日志 | 日志 | 是 | 低 | 最明确的前台日志点 |
| 用户点击推荐决策 | 日志 | 是 | 低 | 例如“丢到项目 / 丢到收集箱” |
| 来源确认 / 权属确认 | 日志 + 证据 | 是 | 中 | 取证价值较高 |
| 归档 | 日志 + 证据 | 是 | 中 | 本地落盘后标记归档即可 |
| 导出 / 下载 / 复制发布格式 | 日志 | 是 | 中 | 属于交付动作 |
| 系统提示 / 权限提示 | 轨迹或系统日志 | 默认弱展示 | 低 | 只有在用户行为有结果时才升格 |
| 错误 / 失败 / 阻止采集 | 系统日志 | 视需要 | 中 | 更适合给调试和复盘使用 |

## 访问网站要不要记

建议：

- **要记**，但默认记在轨迹里。
- **不要默认把每次访问都显示成日志点。**
- 只有在以下情况时，才建议升格为日志点：
  - 第一次访问某域名或某关键页面
  - 用户在页面上发生采集、确认、复制、标注等动作
  - 页面访问直接触发了项目决策
  - 用户手动点击“记入日志”

这样做的原因是：

- 访问本身有创作上下文价值；
- 但大量访问会产生噪声；
- 日志流必须保持“动作意义”，不能变成浏览器历史列表。

## 隐私判断

以下数据通常应视为隐私敏感或至少需要说明：

- 访问过哪些网站
- 页面标题、URL、路径
- 页面内采集的正文、图片、链接
- 采集时间、停留时间、切换轨迹
- 用户点击的决策路径
- 项目内的来源确认、权属判断、人类参与度标记

即使数据**只存本地**，也仍然需要：

- 清晰的产品内说明
- 隐私政策或数据说明
- 在权限申请时给出用途解释

## 显示策略

### 前台日志流

适合显示：

- 用户创建项目
- 入库素材
- 采集成功
- 主动记日志
- 确认来源
- 归档
- 导出、交付

### 后台轨迹

适合记录但不强显示：

- 页面访问
- 页面停留
- 标签切换
- 页面刷新
- 采集前后的上下文变化

### 折叠系统项

适合以弱提示存在：

- 权限提示
- 浏览器限制
- 采集失败
- 同步失败
- 恢复成功

## 需要遵守的产品边界

1. **不把轨迹误当日志。**
2. **不把浏览器心跳刷成前台事件。**
3. **不隐藏关键采集事实。**
4. **不允许项目日志被改写或删除。**
5. **可以让素材被编辑删除，但日志本身必须保留真实性。**

## 开发时的判断问题

每新增一种行为，都先问四个问题：

1. 这是用户主动动作，还是系统自动动作？
2. 这是轨迹、日志，还是证据？
3. 用户是否应该在前台看到它？
4. 如果未来要做隐私说明，这条数据是否需要被解释？

如果答案不清楚，优先把它放进**轨迹**，再决定是否升格。
