## 一、产品定位

**OrbiGet Craft = 内容创作的前置工作台 + 内容资产管理 + 过程记录的 AI Agent 系统。**

类比 VSCode：不是每一门语言都最深的 IDE，但是日常搭架子、写出 80% 代码、项目上下文连续的工作台。Craft 对应的是内容创作——

- 在**探索阶段**完成粗加工：收素材、写文、配图、分镜、口播稿、试方向；
- 在**同一项目**里管资产、看过程、让 AI 读懂上下文；
- 需要专业精修时，**导出到剪映 / PR / PS 等工具**；很多内容根本走不到那一步，粗加工成品就能发。

```
探索（Craft 粗加工）→ 试错（改方向 / 换素材）→ 定型
    → 必要时导出精修 → 回来开下一轮
```

### 记录是什么

记录、血缘、版本、日志链是**底层设施**，不是产品故事。

- 没有「能干活」的前置工作台，纯记录平台没有竞争力；
- 记录只在**承重处**露出：版本回退、素材复用、交付可溯、复盘有据；
- 用户感知应是「靠得住」，不是「被记账」。

### 资源语义（不变）

素材 / 资产 / 过程物 / 产物 / 交付物都是资产库里的 `Asset`，靠来源、身份、关系、行为区分，不切孤立子系统。

产品主线（过程层）仍是：

```
Capture → Organize → Create → Deliver → Review
采集 → 整理 → 粗加工创作 → 交付 → 复盘
```

**Create 是价值中心**（用户在这儿干活）；Capture / Organize 是入口与底座；Deliver / Review 是出口与闭环。五层是生产线，不是五个并列产品。

**已废弃**：通用 Schema / Dataflow / View 编排引擎（禁止复活）。「数据流」若出现在旧文档，仅指字段自动填充，不是 BPM。

## 二、用户与深度阈值

### 目标用户

大部分内容创作者**并不专业、也不需要特别深的工具**：自媒体、网文、知识分享、图文笔记、口播/课程、短视频前期。他们要的是：

1. 快速试出方向；
2. 素材和过程别丢；
3. 能带走、能交付、能发出去。

### 深度阈值（工位验收标准）

每个 Scene / 工位的合格线不是「替代专业软件」，而是：

> **用户在这能交出「探索结果」——方向、结构、粗稿、可演示的序列，足以决定下一步，或足以直接发布。**

- 做不到探索结果 → 空壳工位，应补深或砍掉，而不是再开新工位；
- 已能出探索结果 → 保持够用即可，**不参加与专业工具的深度竞赛**；
- 少数用户需要精修 → 逃逸口（导出 / 对接）必须顺，不硬拦。

### VSCode 式边界

| Craft 做 | Craft 不硬做 |
|---|---|
| 搭架子、写/配出大半成品 | 专业级调色、混音、特效、复杂剪辑 |
| 项目内连续上下文 | 跨软件插件生态平台 |
| 粗加工 → 可发布/可导出 | 替代剪映 / PR / PS 的最后 20% |
| 多内容类型前置工位 | 为小众深度牺牲主流路径 |

## 三、五层主线（生产线口径）

### 1. Capture：采集

把浏览器 / 外部信息带入工作台。

- 采集是入口，不是价值终点；
- 尽量自动、低打扰、可回看，保留来源；
- Inbox 只是缓冲区，不是独立工作流层；
- 未进项目的采集不污染项目日志。

### 2. Organize：整理

把素材变成**项目资产**，服务开工与产出。

- 项目是默认组织单位；素材进项目才进创作闭环；
- 来源、Origin、关系、里程碑属于本层；
- 素材可改可删；项目日志只追加；
- 组织可以做深（检索、关联、知识结构），但必须**汇入产出**——只收集不流转才是要避免的停滞；
- 不与 Obsidian / Wikipedia 正面对撞：差异在「组织天然服务 Create → Deliver → Review」。

### 3. Create：粗加工创作（价值中心）

把项目资产变成**可探索、可交付的粗加工成果**。

- 创作发生在项目上下文中：素材、状态、时间线、生成记录同屏可用；
- Scene 是**内容类型的前置工位**（写文章 / 写小说 / 图文 / 短视频 / 音频…），不是并列子产品；
- 工位之间必须**共用**项目、资产库、过程记录、Agent——禁止各工位私有一套素材逻辑；
- AI 生成（文 / 图 / 视频 / 语音）是生产线核心能力：生成物入资产，prompt / 参数 / 版本 / 采用决策入过程；
- 编辑器做到「够用 + 顺手」，复杂效果交给导出后的专业工具。

### 4. Deliver：交付

把成果送到外部可用状态，并留下一次使用记录。

- 本地开放格式（Markdown / PDF / 图 / 包）是基础闭环；
- 交付写入项目日志；可增强签名、时间戳、证据包（分层能力）；
- 交付不是终点表演，是「东西出去了、边界清楚了」；
- **逃逸口是产品的一部分**：对接剪映项目、下载、发布通道，堵了等于赶用户走。

### 5. Review：复盘

基于事实记录，帮用户看见推进、发现断点、决定下一步。

- 基于日志、资产状态、里程碑、导出记录，不伪造结论；
- 回到项目推进，不做泛数据看板；
- 与 Agent 同属「懂这个项目」的智能层，可深可浅，但不替用户做创作决策。

## 四、Scene 与工位准入

### Scene 是什么

- Scene = 某类内容的**前置生产线工位**（组件组合 + 布局 + AI 上下文），创建项目时选定默认场景，可切换；
- 切换场景**只换工具面**，不搬资产、不拆项目；
- 场景由开发者硬编码（`SceneDefinition`），**不做**用户自定义场景构建。

### 一项目多媒介（monorepo 心智）

用户切场景的目的，是让**同一个项目成长为多种媒介产出**（小说 / 音频 / 短视频 / 图文…），而不是在多个小产品之间搬家。

```text
软件 monorepo                    Craft 项目
─────────────────────────────────────────────
项目根 / 仓库                    项目
src/（多包源码）                  各场景手稿（sceneId = 包身份）
docs/（通用草稿，可演进）          写文章手稿
shared libs                      素材库（图/音/视频/链接）
build / pipeline                 场景工位
dist / releases                  交付（Delivery）
git log / CI                     日志链 / 血缘 / 过程
```

**心智模型不是磁盘布局**：不要求项目目录长得像 monorepo。磁盘仍是「一个项目文件夹、文件自由摆放」；**包身份写在数据结构（`Asset.sceneId`）上，不靠物理路径强制分目录**。

### 素材无主 · 手稿有主

| | 素材（图/音/视频/链接） | 手稿（.md 文稿） |
|---|---|---|
| 归属 | **无主**，全项目共用 | **有主**（`sceneId`） |
| 默认可见 | 各场景素材库直接挂 | 只在归属场景的默认列表 |
| 跨场景 | 无需动作 | 必须「导入」动作 |

- 场景默认列表 **strict**：只列本场景手稿（`sceneId` 匹配或标题前缀兼容）；**禁止**把全项目 `.md` 倒进每个场景列表。
- 目录认领 / 通用文件夹用中性 kind（`collection`），**不得**伪装成小说「章」等业务节点。

### 文章是文稿起始点 · 导入 = 复制 + 血缘

写文章是**通用起草池**（对应 monorepo 的 docs/兼可迁移草稿）；特化场景（脚本/章节/口播稿）地位对等，是各自包内源。

- 各场景通过「**从文章导入**」取用文章稿；
- **导入 = 复制**成新手稿，`sceneId` 归当前场景，`originKind=derived`；
- **血缘**：新稿 → 源文章，`Relation.type=derivative`（与口播稿、媒体转码同构）；
- **源文章不动**（不改 `sceneId`、不消失于文章列表）——避免归属来回搬、列表漂移。

| 允许 | 禁止 |
|---|---|
| 文章 → 任意场景导入（复制+血缘） | 场景默认列表互相倒灌 |
| 素材全场景挂载 | 每场景私有第二套素材库 |
| 特化稿只读参考（可选） | 导入时改写/吞掉源稿 |

### 新工位 / 新 Scene 准入

开新 Scene 前必须能书面回答：

1. **用户在这交出什么探索结果？**（一句话，可验收）
2. **属于哪条内容类型的前置生产？** 文 / 图 / 视频 / 音频 / 混合，还是已有工位的附属能力？
3. **是否共用现有项目 / 资产 / 日志 / Agent 底座？** 否 → 不做，先补底座。
4. **主攻深度还是保持够用？** 同一时期主攻工位建议 ≤ 2，其余「可进来、可带走」。

答不清就不做。加 Scene 不是加功能清单，是加一条生产线。

### GenStudio 等生成台

- 定位：Create 层的**生成执行器 + 过程记录**，不是独立内容平台；
- 所有生成物必须落入项目资产与过程，可复用、可追溯；
- 不在生成台内长出与项目脱节的第二素材库。

## 五、项目优先原则

Craft 的中心永远是 **Project**。

项目不是文件夹，是一次创作任务的承载单位：采集进项目、工位在项目内、交付与复盘回项目。

判断标准：

```
能不能让用户在这推进项目？
能不能沉淀项目轨迹（资产 + 过程）？
能不能交出探索结果或交付物？
能不能在需要时带走 / 精修 / 复盘？
```

只让素材变多、却让项目更糊涂的功能，不是高优先级。

## 六、记录与证据（底层设施）

Craft 在干活时记事实，不制造法律结论，也不拿记账打扰创作。

- 项目日志只追加，不改写、不删除；
- 血缘：产物可回溯到原始资产与中间版本；
- 磁盘工作区是权威真相，本地优先；
- 哈希链、时间戳、签名等是**可选增强**，分层提供，不默认噪音化；
- `Asset + 日志 + 关系` 支撑创作事实；`Delivery + 清单` 记录使用行为——两条线分开。

**露出原则**：用户主动需要版本、复盘、交付证明时才强调记录；默认路径是「顺畅干活、自动沉淀」。

## 七、Agent

Agent 是**长在项目上的 AI**，不是通用聊天窗，也不是操作系统。

适合：

- 读项目上下文：素材、文稿、日志、生成记录；
- 辅助粗加工：续写、润色、配图建议、结构建议、找方向；
- 复盘与追问：这周卡在哪、素材用了多少、下一步试什么。

边界：

- **确定动作**走可预期的结果（按钮 / 表单 / 可确认的工具调用），Agent 是执行器不是唯一入口；
- **不确定探索**可以对话；
- 不替用户做权属、法律、最终创作决策；
- 能力扩展（memory / skills / 跨项目检索）必须增强「懂这个项目」，而不是堆通用技能货架。

---

## 八、Free / Creator / Pro

商业分层不破坏前置工作台闭环。

- **Free**：完整走通采集 → 粗加工 → 交付 → 基础复盘；限制活跃项目数，不限制素材数量；
- **Creator**：各层做深（生成额度、工位能力、复盘智能），不是拆掉基础闭环；
- **Pro**：更强过程可信与交付形态（审计、签名、证据包），不是技术名词堆砌。

升级动力 =「我想用得更深」，不是「被挡在门外」。

---

## 九、工程设计原则（实现层）

产品口径可演进，实现纪律不变：

1. **高内聚**：模块按职责切开。
2. **低耦合**：组合与明确接口，不靠巨型文件缠死。
3. **禁止 huge component**：壳只编排；业务进 composable / 域模块 / 可替换面板。
4. **组合复用，禁止复制**：同一能力只实现一份核心，多入口挂载；禁止每 Scene 抄一套。
5. **Scene ≠ Editor**：Scene 是组装态；文本/图片/视频编辑器是可组合元组件。
6. **场景硬编码**：禁止复活通用 Schema / Dataflow / View / 用户自定义工作流引擎。
7. **目录边界**：UI → 垂直域（features）/ AI 域 → shared → adapters；`features/` 不得 import `@/workbench`。

详见 `CLAUDE.md`。

## 十、迭代判断准则

新功能、重构、改版按序回答：

1. **用户在这能交出什么？**（探索结果 / 交付物 / 过程资产）
2. **是否服务前置生产线？**（Capture→Organize→Create→Deliver→Review 的哪一段）
3. **是否共用项目与资产底座？** 有没有长出第二中心？
4. **深度是否达到该工位阈值？** 还是又开了一个 60% 空壳？
5. **是否减少心智负担？** 逃逸口与记录是否顺、是否不打扰？
6. **是否避免孤岛？** 数据只进不出、组织不流向产出、生成不入资产，即孤岛。

优先做**连接层与层**的能力：采集进项目、素材进创作、创作进时间线、时间线进交付、交付触发复盘。

主攻策略：同一时期把 1–2 个工位砸到「可离开外部工具也能出活」，其余保持够用；避免全线铺开、全线平庸。

## 十一、明确不做

| 不做 | 原因 |
|---|---|
| 替代专业精修工具（最后 20%） | 打不过；导出更划算 |
| 纯记录 / 纯收集平台 | 无竞争力 |
| 用户自定义 Schema / 工作流 / 场景构建 | 边界失控，已砍死 |
| 通用 BPM / 审批流 | 个人创作不需要 |
| 为小众深度牺牲主流 80% 路径 | 目标用户是大多数创作者 |
| 各 Scene 私有素材与过程体系 | 工作台会碎成多个 App |
| 生成物不入资产的「黑盒生成台」 | 底层记录失效 |

---

## 十二、一句话

**OrbiGet Craft 让内容创作者在前置工作台里把方向试出来、把粗加工做出来、把资产和过程管起来；要精修就带走，要复盘时一切都在。**
